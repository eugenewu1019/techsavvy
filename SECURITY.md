# Security Policy

## Supported Versions

We release patches for security vulnerabilities for the following versions:

| Version | Supported          |
| ------- | ------------------ |
| Latest  | :white_check_mark: |
| < Latest| :x:                |

## Reporting a Vulnerability

We take the security of TechSavvy seriously. If you believe you have found a security vulnerability, please report it to us responsibly.

### How to Report

**Please do not report security vulnerabilities through public GitHub issues.**

Instead, please report them via:

1. **GitHub Security Advisories** (Preferred)
   - Navigate to the "Security" tab
   - Click "Report a vulnerability"
   - Fill in the details

2. **Email**
   - Send details to: [Your Email Here]
   - Include the word "SECURITY" in the subject line

### What to Include

Please include as much of the following information as possible:

- Type of vulnerability
- Full paths of affected source files
- Location of the affected code (tag/branch/commit or direct URL)
- Step-by-step instructions to reproduce the issue
- Proof-of-concept or exploit code (if possible)
- Impact of the issue and potential attack scenarios

### Response Timeline

- **Initial Response**: Within 48 hours
- **Status Update**: Within 7 days
- **Fix Timeline**: Depends on severity and complexity

### Disclosure Policy

- We will coordinate with you on the disclosure timeline
- We prefer to fully investigate and patch vulnerabilities before public disclosure
- We will credit you in the security advisory (unless you prefer to remain anonymous)

## Security Best Practices

When using this project:

- Keep dependencies up to date
- Follow security best practices for web applications
- Validate and sanitize all user inputs
- Use HTTPS in production environments

Thank you for helping keep TechSavvy secure!
